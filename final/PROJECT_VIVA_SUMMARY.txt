Blood Vault - Blood Bank Management System
Viva Presentation Summary

===============================================================================

1. PROJECT OVERVIEW (Common Knowledge)

Problem Statement:
- Traditional blood bank management relies on manual processes and paper-based records
- Inefficient inventory tracking leads to blood wastage and shortages
- Lack of real-time donor-recipient matching systems
- No predictive analytics for blood demand forecasting
- Poor coordination between blood banks and hospitals

Solution:
A comprehensive digital blood bank management system with ML-powered insights, real-time inventory tracking, automated expiry management, and intelligent donor-recipient matching.

Key Features:
- Digital Inventory Management: Real-time blood unit tracking with expiry monitoring
- Donor Management: Complete donor profiles with blood type compatibility
- Recipient Management: Patient records with urgency prioritization
- Order Management: Automated blood request and fulfillment system
- ML-Powered Insights: Demand forecasting, donor matching, and priority scoring
- Authentication System: Role-based access for different user types
- Dashboard Analytics: Visual insights and operational metrics

4. PROJECT ARCHITECTURE

System Architecture:

Frontend (React.js) <---> Backend (Express.js) <---> ML Service (Flask)
     Port: 3000              Port: 5000              Port: 5001
                                  |
                                  v
                            Database (MongoDB)
                              Port: 27017

Data Flow Architecture:
1. User Interaction: Frontend captures user input
2. API Communication: React sends HTTP requests to Express backend
3. Authentication: JWT tokens validate user sessions
4. Data Processing: Backend processes requests and validates data
5. Database Operations: MongoDB stores/retrieves data via Mongoose
6. ML Integration: Backend calls Flask ML service for predictions
7. Response Delivery: Processed data returned to frontend for display

Component Architecture:
- Modular Design: Reusable React components
- Separation of Concerns: Frontend, backend, and ML as separate services
- RESTful API: Standardized HTTP endpoints for all operations
- Middleware Stack: Authentication, validation, and error handling layers

6. USER JOURNEY & PROJECT ROADMAP

User Types:
1. Blood Bank Staff: Manage inventory, donors, and orders
2. Hospital Staff: Place blood requests and track orders
3. System Administrator: Oversee all operations and user management

Blood Bank Staff Workflow:
1. Login → Dashboard overview
2. Add Donors → Register new blood donors
3. Collect Blood → Add blood units to inventory with collection dates
4. Monitor Inventory → Track blood levels and expiry dates
5. Process Orders → Fulfill hospital blood requests
6. View Analytics → Check ML insights and demand forecasts

Hospital Staff Workflow:
1. Login → View available blood inventory
2. Add Recipients → Register patients needing blood
3. Create Orders → Request specific blood types and quantities
4. Track Orders → Monitor request status and fulfillment
5. Receive Blood → Confirm receipt and update patient records

7. TECHNICAL CHALLENGES & SOLUTIONS

Challenges Faced:
1. API Connectivity: Frontend-backend communication issues
2. Authentication Flow: JWT token management across components
3. Data Synchronization: Real-time inventory updates
4. ML Integration: Connecting Python ML service with Node.js backend
5. State Management: Complex form states and data flow

Solutions Implemented:
1. CORS Configuration: Proper cross-origin setup
2. Token Storage: localStorage with automatic refresh
3. Event-driven Updates: Automatic data refresh after operations
4. REST API Bridge: Express endpoints calling Flask ML service
5. React Hooks: Efficient state management with useState/useEffect
